# 스터디 타이머 - AI 기반 순공 시간 측정 시스템

## 프로젝트 개요

AI 컴퓨터 비전으로 **진짜 공부한 시간**만 측정하는 학습 관리 플랫폼

- 컴퓨터 전면 웹캠으로 졸음, 자리 이탈, 핸드폰 사용을 자동 감지
- 과목별 순공 시간을 일/월/분기 단위로 추적
- 학습 + 생활 목표를 통합 관리하여 효율적인 시간 운용

**기술 스택**: Python Flask + HTML/JavaScript + MediaPipe + YOLO Tiny

---

## 문제 정의 - 공부 시간의 착각

학생들이 겪는 가장 큰 문제: **"앉아있는 시간 ≠ 공부한 시간"**

| 착각 | 현실 |
|------|------|
| "오늘 10시간 공부했다" | 실제 집중 시간은 5~6시간 |
| "핸드폰은 잠깐만 봤다" | 하루 합산 1시간 이상 사용 |
| "집중을 잘 했다" | 시선 강탈 30회 이상 발생 |
| "모든 과목 골고루 했다" | 좋아하는 과목에 70% 편중 |

수험생 설문 결과, 체감 공부 시간과 실제 순공 시간 사이에 **평균 30~40% 차이**가 존재합니다.

## 솔루션 - AI가 지켜보는 순공 타이머

컴퓨터 전면 웹캠 하나로 모든 비집중 행동을 자동 감지합니다.

| 감지 항목 | 방법 | 결과 |
|-----------|------|------|
| 😴 졸음 | 눈 감김 비율(EAR) 측정 | 타이머 자동 정지 + 알림 |
| ⚪ 자리 이탈 | 얼굴 미검출 | 타이머 자동 정지 |
| 📱 핸드폰 사용 | YOLO 객체 감지 | 사용 시간/횟수 기록 |
| 👀 고개 돌림 | 얼굴 회전 각도 분석 | 비집중 시간 기록 |
| 🥱 하품 | 입 벌림 비율(MAR) | 피로도 추정 |

**집중할 때만 타이머가 돌아갑니다** → 진짜 순공 시간 추출

## 페르소나 1 - 수험생 김민수 (25세)

**프로필**

| 항목 | 내용 |
|------|------|
| 직업 | 공무원 시험 준비생 (2년차) |
| 과목 | 국어, 영어, 한국사, 행정법, 행정학 |
| 학습 환경 | 독서실, 노트북 내장 웹캠 |
| 일일 목표 | 순공 10시간 |

**핵심 고충**

- "하루 12시간 앉아있는데, 실제 집중은 얼마나 했는지 모르겠다"
- 핸드폰 알림에 자주 시선을 빼앗김
- 점심 후 졸음이 심하지만, 얼마나 졸았는지 파악 어려움
- 과목별로 얼마나 투자했는지 정확히 기록하고 싶음

**니즈**: 과목별 실제 집중 시간을 **객관적 수치**로 확인하고, 낭비 시간을 줄이고 싶음

## 핵심 목표

프로젝트의 5가지 핵심 목표:

**1. 순공 시간 자동 측정**
웹캠 + MediaPipe로 실제 공부 중인 시간만 기록. 졸음, 이탈, 핸드폰 사용 시 자동 차감.

**2. 과목별 시간 관리**
과목을 선택하고 해당 과목에 투자한 순공 시간을 분리 기록. 과목 전환도 원클릭.

**3. 전일 행동 감시**
핸드폰 사용 횟수/시간, 시선 이탈 횟수, 졸음 횟수 등 비집중 행동을 정량적으로 포착.

**4. 다차원 대시보드**
일간/월간/분기별 순공 시간·행동 패턴·목표 달성률을 차트로 시각화.

**5. 행동 리포트**
"오늘 핸드폰 47분, 시선 이탈 23회" 같은 정량적 피드백으로 행동 개선 유도.

## 유저 시나리오 1 - 첫 사용: 과목 설정

사용자가 처음 서비스에 접속하여 세팅하는 과정:

**Step 1**: 웹 브라우저에서 스터디 타이머에 접속하고 회원가입

**Step 2**: "과목 관리" 메뉴에서 과목 목록 등록
- 국어, 영어, 한국사, 행정법, 행정학

**Step 3**: 각 과목별 일일/월간/분기 목표 시간 설정
- 행정법: 일 2시간 / 월 50시간 / 분기 140시간

**Step 4**: 생활 목표 등록 (선택사항)
- 운동 주 3회, 독서 일 30분

**Step 5**: 웹캠 접근 권한 허용
- 브라우저에서 카메라 권한 요청 → 허용
- 얼굴 인식 테스트 → 정상 감지 확인

**Step 6**: 사용 준비 완료!

## 유저 시나리오 2 - 공부 시작: 순공 타이머

**공부 시작 과정:**

1. 과목 선택 드롭다운에서 "행정법" 선택
2. "공부 시작" 버튼 클릭
3. 웹캠 활성화 → MediaPipe가 얼굴 감지 시작
4. 화면에 실시간 상태 표시:

| 상태 | 색상 | 타이머 동작 |
|------|------|-------------|
| 🟢 집중 중 | 초록색 | 순공 타이머 가동 |
| 📱 핸드폰 사용 | 빨간색 | 타이머 정지 + 사용 시간 기록 |
| 😴 졸음 | 노란색 | 타이머 정지 + 알림음 |
| 👀 고개 돌림 | 주황색 | 타이머 정지 |
| ⚪ 자리 이탈 | 회색 | 타이머 정지 |

5. 과목 변경 시 "과목 변경" 버튼 → 새 과목 선택
6. "종료" 버튼 클릭 → 세션 요약 리포트 표시

## AI 비전 파이프라인 - 전체 흐름

웹캠 영상이 행동 분류까지 처리되는 과정:

**처리 흐름:**

1. **웹캠 입력** → 브라우저 getUserMedia로 영상 캡처 (640×480, 30fps)
2. **MediaPipe 분석** → Face Mesh 468 랜드마크 검출
3. **얼굴 유무 판정** → 미검출 1초 이상 → 자리 이탈
4. **EAR 계산** → 눈 감김 비율 < 0.20 연속 1.5초 → 졸음
5. **고개 방향** → yaw > 30° 또는 pitch 범위 이탈 → 비집중
6. **YOLO 객체 감지** → 핸드폰 감지 → 핸드폰 사용
7. **종합 상태 결정** → 우선순위: 이탈 > 졸음 > 핸드폰 > 비집중 > 집중
8. **행동 로그 저장** → DB에 {시작, 종료, 상태, 지속시간} 기록

**처리 속도**: 비전 분석은 10fps (3프레임당 1회)로 제한하여 CPU 부하 감소

![AI 비전 파이프라인 흐름도 - 웹캠에서 행동 분류까지의 데이터 흐름](image: AI vision pipeline flowchart showing data flow from webcam capture through MediaPipe face analysis to behavior classification)

## 알고리즘 1 - 자리 이탈 감지

**MediaPipe Face Mesh**로 얼굴 존재 여부를 판정:

**알고리즘 로직:**

| 단계 | 처리 | 설명 |
|------|------|------|
| 1 | 프레임 입력 | 웹캠에서 640×480 프레임 캡처 |
| 2 | Face Mesh 실행 | 468개 얼굴 랜드마크 검출 시도 |
| 3-A | 얼굴 검출됨 | 미검출 카운터 = 0, 상태 = "존재" |
| 3-B | 얼굴 미검출 | 미검출 카운터 +1 |
| 4 | 임계값 비교 | 카운터 ≥ 30프레임 (약 1초) |
| 5 | 이탈 판정 | 상태 = "자리 이탈", 타이머 정지 |

**왜 1초 디바운싱?**
- 순간적으로 고개를 숙여 교재를 보거나 물을 마실 때 얼굴이 잠시 미검출될 수 있음
- 1초 미만의 미검출은 오탐으로 간주하여 무시

## 알고리즘 2 - 졸음 감지 (EAR)

**EAR (Eye Aspect Ratio)** = 눈의 세로/가로 비율로 졸음 판별:

**EAR 계산 공식:**

EAR = (|P2-P6| + |P3-P5|) / (2 × |P1-P4|)

- P1, P4: 눈의 양쪽 끝 (가로)
- P2, P3, P5, P6: 눈의 위/아래 (세로)

**정상 vs 졸음 상태:**

| 상태 | EAR 값 | 판정 |
|------|--------|------|
| 눈 크게 뜸 | 0.30+ | 정상 |
| 눈 보통 | 0.25 | 정상 |
| 눈 살짝 감김 | 0.20 | 경계 |
| 눈 감김 (깜빡임) | 0.15 | 0.3초 미만이면 정상 깜빡임 |
| **눈 감김 (졸음)** | **< 0.20 연속 1.5초** | **졸음 판정 → 알림** |

**졸음 전조 감지**: EAR이 최근 5분간 점진적으로 하락하는 추세 감지 → "졸음이 올 수 있어요" 사전 알림

![EAR 계산 다이어그램 - 눈 랜드마크 6개 포인트와 거리 표시](image: eye aspect ratio diagram showing 6 landmark points P1-P6 on the eye with vertical and horizontal distance measurements)

## 알고리즘 3 - 집중도 판별 (고개 방향)

**얼굴 회전 각도**로 집중 여부를 판별:

**측정 각도 3가지:**

| 각도 | 의미 | 집중 범위 | 비집중 판정 |
|------|------|-----------|-------------|
| **Yaw** (좌우 회전) | 고개를 옆으로 돌림 | -30° ~ +30° | \|yaw\| > 30° |
| **Pitch** (상하 기울기) | 고개를 숙이거나 젖힘 | -35° ~ +25° | pitch > 25° 또는 < -35° |
| **Roll** (좌우 기울기) | 고개를 옆으로 기울임 | -20° ~ +20° | 참고용 (단독 판정 안 함) |

**solvePnP 방식:**
- Face Mesh에서 코끝(1), 턱(152), 눈꼬리(33, 263), 입꼬리(61, 291) 좌표 추출
- 3D 모델 좌표와 2D 이미지 좌표를 매칭
- 회전 벡터 → 오일러 각도 변환

**디바운싱**: 비집중 상태가 **2초 이상 연속** 지속해야 타이머 정지 (잠깐 옆을 보는 건 허용)

![고개 방향 3축 회전 다이어그램 - Yaw, Pitch, Roll 각도 표시](image: head pose estimation diagram showing three rotation axes - yaw left-right, pitch up-down, roll tilt - with angle ranges)

## 데이터 모델 (ER 다이어그램)

시스템의 핵심 데이터 구조:

**테이블 구조:**

| 테이블 | 주요 필드 | 설명 |
|--------|-----------|------|
| **User** | ID, 이름, 이메일 | 사용자 정보 |
| **Goal** | ID, User_ID, 유형, 이름, 목표시간 | 학습/생활 목표 |
| **Subject** | ID, Goal_ID, 과목명 | 학습 과목 |
| **Session** | ID, Subject_ID, 날짜, 시작/종료, 순공시간, 순공률 | 학습 세션 |
| **BehaviorLog** | ID, Session_ID, 행동유형, 시작/종료, 지속시간 | 행동 기록 |
| **CheckItem** | ID, Subject_ID, 항목명, 완료여부 | 진도 체크 |

**관계:**
- User → Goal (1:N): 한 사용자가 여러 목표
- Goal → Subject (1:N): 한 목표에 여러 과목
- Subject → Session (1:N): 한 과목에 여러 세션
- Session → BehaviorLog (1:N): 한 세션에 여러 행동 기록

- 전면 웹캠: 얼굴 분석 (졸음, 표정) 유지

- 두 카메라 데이터를 결합하여 **정밀한 행동 분류**
